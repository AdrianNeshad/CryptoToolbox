# SLIP-39 tool — tests

Known-answer and property tests for `lib/slip39.js` and `lib/bip39.js`. Fully
offline; uses only the tool's own code plus the vendored bitcoinjs (for the
BIP-32 xprv check) and the BIP-39 wordlist already in the repo.

```bash
node tools/SLIP39/test/node-test.cjs
```

## What is covered

| Test | Source of truth |
|------|-----------------|
| All 45 cases of the official vector file: valid sets combine to the given master secret **and** BIP-32 xprv (passphrase `TREZOR`), invalid sets are rejected | `vectors.json`, verbatim from trezor/python-shamir-mnemonic |
| The flexible recovery used by the UI agrees with strict combining on every valid vector, and tolerates surplus shares | same vectors |
| Every decodable vector share re-encodes to identical words | same vectors |
| Random round trips: 8 schemes × 128/256/512-bit, extendable and not, iteration exponents 0–2, with and without passphrase | — |
| Scheme / length / passphrase validation | SLIP-0039 spec |
| Re-sharing an extendable backup under a new identifier keeps the wallet for every passphrase | spec, “Extendable backup flag” |
| Regenerating lost member shares and a lost 1-of-1 group reproduces them word for word | — |
| A valid-checksum share from a different polynomial is detected and skipped | — |
| Word repair: 1–3 `?` words, one wrong / missing / extra / swapped word, two wrong words (deep search) | — |
| BIP-39 checksum, seed (`abandon … about` + `TREZOR`) and a 59-word conversion round trip | BIP-39 reference vector + Node's PBKDF2 |

## Cross-check against the reference implementation

During development, 30 share sets generated by this code (all lengths, both
flag values, several schemes and passphrases) were combined by the official
Python reference implementation, 150 random subsets, with no mismatches. That
check needs the Python package and is not part of this offline suite.
