SLIP-39 Shamir Backup

Split a wallet seed into Shamir shares (SLIP-0039, as used by Trezor), recover the master secret from shares, inspect and repair damaged shares, and extend or regenerate an existing backup. Everything runs locally in this window — nothing is uploaded, stored or sent anywhere.

1 Master secret

The value that gets split. For a wallet this is the BIP-32 master seed. Pick a fresh random secret, enter one as hex, or convert an existing BIP-39 recovery phrase.

Strength

A new secret is drawn from the browser's cryptographic random number generator each time you press Create shares.

16–64 bytes, an even number of bytes (128, 160, 192 … 512 bits).

The phrase and passphrase are turned into the 512-bit BIP-39 seed, which becomes the SLIP-39 master secret — so each share will be 59 words. Restoring the shares on a SLIP-39 wallet opens the same accounts as the BIP-39 phrase did (the BIP-39 passphrase is already baked in).

2 Sharing scheme

A share set has 1–16 groups; each group has 1–16 member shares and its own threshold. Recovery needs the group threshold’s number of groups, each with enough of its own shares.

3 Passphrase & options

An optional SLIP-39 passphrase encrypts the master secret before it is split. There is no way to check a passphrase: every passphrase opens a wallet, so a typo silently gives an empty one. Printable ASCII only.

1 Shares

Paste your shares, one per line (a share wrapped over several lines works if blank lines separate the shares). Order doesn't matter, extra shares are fine, and the first four letters of each word are enough. Lines starting with # are ignored.

1 One share

Paste a single share to decode every field and check it. Write ? for a word you can't read — the checksum can restore up to three of them. A misspelt or unknown word is treated the same way.

1 Existing shares

Paste the shares you have, one per line. What you can do depends on how many you have: a group’s threshold of shares is enough to regenerate any share of that group; a full recovery set is enough to create a whole new share set.

2 What to do

Creates an additional, independent share set for the same wallet — for example to move from a single share to 2-of-3, or to replace a set whose shares may be compromised (the old shares keep working, so destroy them). The new set gets a new identifier, so its shares can't be mixed up with the old ones.

Rebuilds the share with a given member index from the threshold number of shares of the same group. If that index was part of the original set, the result is word-for-word identical to the lost share. (Shares don't record how many members a group had, so indices beyond the original count give valid new shares.)

Rebuilds a whole group from a full recovery set (the group threshold’s number of complete groups). A 1-of-1 group is reproduced exactly. For a group with a higher threshold the original polynomial can’t be known, so a fresh member set is created — it works with the other groups, but not together with surviving shares of the old group.
